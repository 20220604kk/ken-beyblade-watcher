# 日亞登入狀態拆分（2026-10-19）

## 已確認的錯誤

原本直購線在待機時建立訂單基準，約每 20 秒刷新。商品頁已回傳 HTTP 200 並正常回報缺貨後，背景訂單頁若導向登入或驗證頁，錯誤會一路拋到購買流程，把整個任務設成 needs_login / needs_verification。

離線重現：商品 GET 正常、背景 order-history GET 導向登入，原版就停止商品輪詢。這與「使用者打開商品頁仍已登入」可以同時發生。視窗接續修正不等於這個判定已修好。

## 本次處理

- HTTP 錯誤保留原始操作類別：product、checkout、order_history、order_detail、cart、other。登入跳轉後仍屬於原操作；不記錄 Cookie、跳轉 query 或工作階段識別。
- 待機訂單基準屬於選用輔助功能。其登入／驗證只暫停背景查單，以 orderHistoryCheck 獨立保存並在展開區顯示。商品輪詢及符合條件的直購繼續；不持續每 20 秒撞同一驗證。明確完成登入核對或重設任務後可以重新嘗試。
- 背景查單無法取得列表時清除記憶體中的舊基準，絕不改成空訂單列表。一般讀取故障以至少 5 分鐘間隔再查。
- 待機購物車整理登入／驗證也只暫停該整理功能，不改商品或購買登入狀態。
- 商品頁與結帳的真實登入／人工驗證保留各自判定，仍須由使用者完成官網驗證。真正 429／503／Retry-After 維持帳號請求降速。
- 最終送單結果不明仍保留交易鎖；缺單號且沒有可信訂單基準時維持待核對，不猜成功、不重送。

## 驗證

新增離線回歸覆蓋 ABC：查單導向登入／CAPTCHA後連續商品輪詢與後續合成訂單成功、查單暫停跨執行器保存、讀取故障退避、官網限流、商品／結帳真實驗證、最終送單待核對、清車驗證、診斷不洩漏 query，以及實際控制台分開顯示輔助狀態。

所有交易測試使用合成商品／假訂單；不使用真實帳號送測試單。正式商品頁未再次要求登入，不代表未來結帳一定免驗證。

完整單程序回歸 1059 / 1059 通過。已安全重載，正式控制台頁面無程式錯誤；A 保持原本啟用與目標 3 張，API 刷新持續增加，lastError 為空。B／C 保持停用，已移除的插件未重新連線。
