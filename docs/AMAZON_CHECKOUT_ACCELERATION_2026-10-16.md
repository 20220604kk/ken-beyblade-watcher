# 日亞 A 線加速與漏判修復

日期：2026-10-16，Asia/Taipei。與前一輪「監控／下單拆線」不同，本輪修改報價判讀與實際結帳路徑。

## 1. 官網唯讀發現的確定錯誤

使用一般 Chrome 既有登入環境，只讀購物車、CX-20 AOD 報價及商品頁；沒有按加車、改購物車或提交任何訂單，也沒有讀取／匯出 Cookie、CSRF 值或付款資料。

- CX-20：`B0HMGJCGVN`。
- 官網 AOD 的 11 筆報價，商品狀態標籤實際為 **全新品**。
- 舊式 `^(?:新品|全新|New)(?:\s|$)` 不接受「全新品」。「全新」後還有「品」，並非空白或字尾，因此會判為非全新。
- 新式接受「全新品／全新／新品／New」，仍拒絕「非全新品／二手／中古品／Used／Renewed／新品同様」。賣家、原價、表單和限購護欄均未放寬。
- 當次實際可見報價是第三方 ¥14,141 起，未見 Amazon.co.jp 自營報價，不能拿這次報價測試購買，也不能倒推 10/15 所有錯過都由上述錯誤造成。

唯讀來源：[CX-20 AOD](https://www.amazon.co.jp/gp/product/ajax/aodAjaxMain/ref=dp_aod_unknown_mbc?asin=B0HMGJCGVN&pc=dp&isonlyrenderofferlist=false)、[商品頁](https://www.amazon.co.jp/dp/B0HMGJCGVN)。一般 Chrome 與任務 A 是不同工作階段；不能用其中一方的可購狀態保證另一方可購。

## 2. 下單路徑的變更

僅 A API 且已啟用 `fastLane` 的任務使用 `fastCheckout`。B／C 與明確保留的瀏覽器模式不自動切換。刷新目標仍 2 秒，沒有靠提高請求密度製造成效。

### 接續精確目標購物車

原本一律要求原車空車；現在以下條件全部滿足才可接續：

1. 本輪 AOD 已確認目標 ASIN、全新、自營及符合原價的有效加車契約。
2. 官方購物車總數為 1，且活動購物車只含目標 ASIN ×1。
3. 商品列確認賣家為 Amazon.co.jp。
4. 車內 `data-encoded-offering` 與本輪 fresh offerListingId 精確核對（僅解開一次 URL 編碼）；缺欄位、不一致或非法編碼都停下。
5. 進入結帳後仍核對 ASIN、型號、數量、賣家、配送、JPY、含運總額、運費與不折點數，保存送單意圖後才可送單一次。

相對於空車重新加車的完整路徑，此分支不做加車 POST，也不再查一次加車後購物車，減少兩次請求。這不是已測得的秒數；也不是「同 ASIN 就接車」。

唯讀時一般 Chrome 活動車為空；已保存商品確有 `data-encoded-offering` 欄位，但其舊報價識別沒有命中當次 AOD。這些舊保存商品 **不符合接車條件**。本輪沒有建立活動購物車來驗證此分支；正式可用性與省時仍需授權測試。

### 重用完整加車回覆

若加車回覆本身含有可核對的完整活動車（總數 1、只有目標 ASIN ×1、自營商品列），可用它做購物車核對，少一次 GET。只有「已加入」文字、車數標籤、資料不完整或加車逾時都仍查車，不重加。

兩個捷徑是依情境擇一，不把「省兩次」與「省一次」加成每單省三次。

## 3. 診斷與計時

- `diagnostic.decision` 區分無報價、無自營、未確認全新、自營表單不完整、自營價格讀取失敗。
- 同時保存自營／全新／可加車筆數及必要欄位缺失的原因計數；不保存欄位值、賣家報價識別、CSRF、原始 HTML 或 Cookie。
- 監控訊號命中後的決策最多保留 40 筆於該任務 `signalChecks`，一般輪詢不建立訂單紀錄。
- UI 對表單不完整、價格無法辨識明確顯示「非判定售罄」。
- AOD 額外記錄 `responseMs`（含回應讀取、通用 HTML 解析與頁面檢查）、`offerParseMs` 與既有整段 `quoteMs`；不是純網路 RTT。
- 結帳請求記錄類別與耗時，不記網址、查詢參數或 flow ID。一般報價輪詢不新增一次同步狀態檔寫入。
- 接車起點使用 `api_cart_resume`，歷史耗時不會因沒有 `api_add_cart` 而全部消失。

## 4. 驗證界線

離線測試涵蓋全新品漏判、第三方／中古排除、每種報價拒絕原因、精確接車、混車／超量／報價不符拒絕、結帳全部護欄、POST 結果不明只查單、取消／停止不提交、加車回覆重用與不完整時補查，以及 A 才啟用捷徑。測試單號與頁面均為合成資料。

未建立新的正式訂單，沒有新的端到端實站成交耗時；不能宣稱快幾倍或提高多少成功率。

## 5. 立即購買仍未接入

唯讀確認商品頁有 `submit.buy-now`，表單 POST 至 `/gp/product/handle-buy-box/…`，包含 `pipelineType`、`isBuyNow`、ASIN 與當次報價等欄位。

這只是入口與欄位名稱證據，還沒驗證伺服器實際收取的契約、配送／付款中間頁與正式單號。因此不拼 body、不重播舊 token，也不拿第三方高價報價實測。需另行確認加車／送單測試商品與金額範圍後才可比較。
