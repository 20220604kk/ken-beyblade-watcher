# ATM 優先與 7-11 貨到門市設定規則

依使用者 2026-10-09 的規則：兩平台優先宅配 ATM。7-11 貨到付款須先由使用者在官方完成選店及成立真實訂單，才可用該帳號與門市進行自動購買。本次不主動建立設定訂單。

## 實作

- 預設付款改為 ATM；正式服務第一次載入此政策時，把目前各帳號付款改為 ATM，保留加密資料與門市範本。政策版本保存後不會在每次重啟強行改回 ATM。
- 未核對貨到正式訂單的帳號，其貨到選項鎖定；伺服器也拒絕儲存未解鎖的貨到設定。佇列與購買器在清車／加車前再次攔截。
- 每個帳號的「帳密設定」中新增「核對門市訂單」。FUNBOX 填官方訂單詳細頁連結；誠品填正式訂單編號。
- 核對只做官方 GET，不清車、不選店、不送單、不推播。FUNBOX 必須是本帳號官方訂單列表中的連結，付款與門市明細吻合；誠品由本帳號登入 API 讀取正式列表和明細。
- 只有核對成功才在加密資料中保存證據，按平台／帳號身分／門市隔離。換帳號或換門市不沿用另一份證據。正式核對不會自動把付款從 ATM 切成貨到，仍由使用者自行選擇。
- 模擬到最後一步、地址簿資料或 ATM 訂單，都不能解鎖貨到。

## 驗收與限制

新測試涵蓋預設 ATM、GET-only 核對、訂單所有權、付款方式、跨帳號／平台／門市隔離、加密保存、寫入失敗回滾、送單前攔截及控制台入口。完整測試 644 項通過，0 失敗（後續新增的必填地址檢查另有針對測試）。

FUNBOX 官方既有訂單的明細 DOM 已做唯讀觀察。誠品宅配 ATM 明細結構已做唯讀觀察，但本次沒有可用的 7-11 貨到實單驗證付款 enum；未知格式會維持鎖定，不能把測試 fixture 當成店家實單驗證。真實門市回應格式若不符合目前辨識規則，需要用實單的安全欄位結構補齊，不能跳過檢查。

正式重載須避開正在送單的工作；如果有新登入／驗證視窗，須取得使用者允許中斷後才重載。
