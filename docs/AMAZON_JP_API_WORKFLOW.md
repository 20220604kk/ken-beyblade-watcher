# 日亞單品：API 主線

日亞 A／B／C 單品任務預設改為 API 報價、加車、結帳與官方查單。沿用各任務的持久登入資料；網頁只用於登入、人工驗證及使用者處理。這是官網自身 HTTP 契約，不是 Amazon 公開購買 API。

2026-10-16 更新：修復官網「全新品」標籤漏判；A 的 API 快線可在確認同一 fresh 報價的精確單品車時接續結帳，也可重用完整加車回覆，避免多餘往返。其餘情況仍採下列保守流程。條件、證據及未實測部分見 [本輪加速說明](AMAZON_CHECKOUT_ACCELERATION_2026-10-16.md)。

## 範圍

- 修改日亞**已指定 ASIN 的單品任務**，不是改 FUNBOX／誠品，也不是把日亞商品探索搜尋改成 AOD。一般原價搜尋監控仍提供新品／補貨訊號。
- 原「訊號觸發」與「五秒＋訊號」模式、商品、成功次數及運費上限不變。五秒線直接 GET AOD 報價，不重新載入商品頁。
- API 使用每個持久 BrowserContext 的 request Cookie jar，登入資料不寫入臨時交接檔、不列出請求頭。仍需一次啟動登入工作階段，不代表完全不使用 Chrome。
- 同一任務一次一個檢查／交易，訊號合併；A／B／C 初次輪詢錯開。請勿同時手動操作正在結帳帳號的購物車，亦勿把同一 Amazon 帳號配置到多條任務。
- 正式預設 API。`checkoutTransport: "browser"` 僅保留明確的人工設定回退；API 遇錯**不自動切網頁下第二張單**。

## 步驟

| 步驟 | 動作 |
| --- | --- |
| 01 | API 讀 AOD；只取目標 ASIN、全新、Amazon.co.jp **自營**、官方原價容許範圍的報價 |
| 02 | API 確認原購物車空車，再保存官方訂單列表基準；新帳號已確認無訂單也可使用 |
| 03 | 保存加車意圖，使用當次官方 offer／CSRF，POST 加車一次、數量 1 |
| 04 | API 查車，必須只有目標商品 1 件；逾時不重加 |
| 05 | 依官方 GET `/checkout/entry/cart` 表單取得結帳資料；未知頁型保留車並暫停 |
| 06 | 核對商品、ASIN、數量、自營、配送、JPY、含運總額及不折點；預設運費上限 ¥500 |
| 07 | 保存送單意圖，核對 fresh 契約，再 POST 正式送單一次 |
| 08 | 查官方訂單列表／詳情；新正式單號、商品、數量、賣家與金額唯一核對後才記成立 |

**Amazon 既有購物車不自動清空。** 這與 FUNBOX／誠品的清車策略不同，避免刪除使用者私人商品。已加車後失敗，也不清車或重新加一份。

不呼叫點數折抵表單。若結帳已有折點、金額未知或商品金額與當次報價不一致，不送單，請人工處理；不能把折點後的低價當成通過原價檢查。

## 例外與恢復

- HTTP 429／503 或 Retry-After：至少等 60 秒，遵守更長期限；不換 IP、帳號或改前端繞過限制。
- 送單 POST 碰到限流亦保留未知交易，人工查單按鈕不能跳過降速期限。
- 登入失效／驗證：停止該任務，使用「登入／驗證」由使用者處理。
- 加車逾時：只查車一次，精確確認目標 1 件才可前進；否則暫停人工核對。
- 送單逾時：只讀查單，最多兩輪列表、每輪最多五筆新單詳情；無法唯一確認則 `needs_review`。這是查單上限，不是送單重試。
- 送單結果不明：控制台「查官方訂單（不重送）」；只查、不 POST。
- 尚未送單的購物車問題：使用者手動處理車後，按「已手動核對／清車，API 再確認」。官方空車確認後才解除暫停；不能用此按鈕解除曾送單的交易。
- 程式重啟：保留未核對的交易意圖；不靠重設進度清除它。
- `purchaseId` 是流程識別，不作正式單號。正式單號來自官方 order-card／詳情或明確訂單編號標籤。

## 驗證界線

先前限定商品的獨立 HTTP 實單曾走通一次；本次正式化修改**不建立新實單**。離線模擬測試覆蓋完整 API 鏈、斷線、混車、超價、運費、第三方、折點、驗證、限流、跨網域、POST 不重送、重啟保護及只讀查單。它們不等於每個帳號的目前真實結帳契約已實測，也不保證補貨成功率。

實際 API 回覆缺少身份／金額／配送證據時，會明確停在待核對，而不是放寬條件或宣布成功。最新部署與只讀核對結果以本次交付說明為準。
