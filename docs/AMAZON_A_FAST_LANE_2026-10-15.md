# 日亞 A 線加速研究（2026-10-15）

## 範圍

只調整 A 線 API，保留原目標 ASIN、原價／Amazon.co.jp 自營／一件商品／運費上限與不折點規則。不新增測試商品，不為研究加車或建立真實訂單。B／C 維持 5 秒輪詢及原下單流程。

## 已實作

- A 設定 `fastLane: true` 且採 API 時，雙線刷新目標間隔改為 2 秒。設定可從 A 的「快線研究」勾選後儲存；取消即回到 5 秒。網頁路線不套用快線。
- 每次刷新仍等待上一輪結束，不重疊、不補打落後的輪次。訊號可立即觸發，但不能繞過帳號鎖、結帳中暫停與官方冷卻。
- 前置空車 GET 與歷史訂單 GET 改為同時讀取。兩項完整成功才可加車；失敗也等待兩個請求結束，優先保留官方 Retry-After。沒有共用舊購物車或舊訂單快取。
- A 進入購買階段時使用立即寫入的安全檢查點，不再等待一般狀態存檔的 350ms 合併計時器。加車、送單之前的耐久檢查點仍保留。
- A／B／C UI 顯示完整商品名稱、ASIN；名稱只取同 ASIN 的報價或資料庫。換商品後不借用舊品名／價格。查不到時顯示待辨識。
- UI 顯示 API 報價含解析耗時。永久紀錄增加刷新至送出時間，不把送出後查單誤算為送單前等待。

## 可證明與不可證明

5 → 2 秒是排程目標，不代表官網每 2 秒一定回覆，也不代表下單快 2.5 倍。若補貨時點均勻且每次都正常完成，單純等待下輪的理論平均值從 2.5 秒降到 1 秒；這不是實單測量。

並行前置檢查把兩項讀取的串行等待改為較慢一項的等待，仍有解析及存檔成本。沒有刪除任何購買核對。實際送單改善秒數仍須日後在授權交易中取得同口徑時間，不能以離線測試冒充成功實單。

「API 立即購買」尚未作為正式路線：先前只觀察過官網表單，尚未證明完整安全契約。這次不重播舊 token／送單 body，也不為搶速度移除查車或未知結果保護。

- `node --test test/amazon-a-fast-lane.test.js test/amazon-jp-http.test.js test/amazon-order-history.test.js`
- 完整 `npm test` 與 `npm run check`。
- `node scripts/amazon-a-refresh-observation.mjs 30 baseline-5s`／`30 fast-2s`：只讀本機狀態，觀察既有 A 線，不自行查 Amazon、不加車、不送單。實測資料存於 Git 忽略的 `data/records/amazon-a-speed/`。
- 短期讀取結果不能當作長期不受限保證；429／503／驗證或官方 Retry-After 仍停止該輪並降速。

## 現場唯讀觀察結果

2026-10-15 台灣時間 01:32–01:36，同一 A 線 ASIN `B0HMGJCGVN`（CX-20 カスタマイズセット C）。只觀察原本已啟用任務的報價輪詢，研究工具沒有請求 Amazon、加車或送單。B 仍停用；C 仍為 5 秒。

| 樣本 | 刷新完成間隔 P50 | P95 | 報價含解析 P50／P95 |
| --- | --- | --- | --- |
| 原 5 秒設定，30 秒觀察、7 筆 | 5,017ms | 5,035ms | 舊版未記錄，不補造 |
| A 快線，40 秒觀察、21 筆 | 2,009ms | 2,100ms | 472ms／518ms |

以上是資料刷新完成時間的間隔，不是每次網路請求延遲，也不是送單耗時；兩段先後觀察而非同時對照。兩段均完成觀察，沒有遇到官方冷卻／驗證中止。這是短期可用證據，不是長期流量限制或補貨成交保證。

新下單前置並行與單次送出保護已做離線模擬驗證，本次沒有新實單，因此送單加速秒數尚未實測。
