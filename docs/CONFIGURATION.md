# 本機設定

## 初次啟動

由 `install.bat` 建立 `.env` 與 `config.json`。兩份範例不含真實帳號及訂單；安裝器不覆蓋既有設定。監控與購買分開啟用，下載後不會自動建立訂單。

`config.example.json` 提供儀表埠、監控間隔、時段與停用的購買預設。購物來源未指定時，主程式會建立已支援的公開來源預設；來源名稱不代表官網可用性或購買就緒。

帳號、付款、收件資料、黑白名單與合單條件應在本機控制台設定。新帳號不繼承他人身分或登入憑證；共用收件資料不等於可共用門市契約。

## 通知

`.env.example` 的 Discord 公開 Webhook 用於新品與庫存；私人 Webhook 用於訂單、付款與錯誤。Bot token 與 LINE channel access token 為選用整合。不需要提供 LINE Pay 密碼。

所有 token 只填入本機 `.env`，不要寫到 README、Issue、提交或截圖。控制台可保存帳號；`.env` 的帳密欄位只保留舊版匯入相容性。

## 可選售價試算表

在 `.env` 設定 `PRODUCT_CATALOG_SHEET_ID` 與 `PRODUCT_CATALOG_SHEET_GID`，重新啟動發佈副本後生效。留空時不讀取任何預設 Google 試算表。

只接受 Google 試算表 ID 與數字分頁 gid，不接受任意遠端伺服器網址。使用有權讀取且可匯出 CSV 的試算表；本功能不取得 Google 帳密、cookie 或登入 token。

CSV 四欄標題需依序為 `型號`、`品項`、`售價（NT$）`、`類型`。按內容分為 BX、UX、CX、配件、聯名、對戰盤；格式無效時顯示錯誤，不把缺失售價當成零元。顯示／嵌入原表需要使用者自行分享的讀取權限。

## 帳號規則

範例誠品採 `buyMode: whitelist`，兩平台白名單預設留空。優先關鍵字不會把未通過白名單的商品變成購買資格；黑名單優先。

FUNBOX 的一般款每日一件、隨機強化組每日三件與台灣午夜日期桶，是本工具使用的本機政策，不能視為平台官方承諾。誠品已購排除亦依本機／同步紀錄判斷，官網限購仍優先。

運費上限、取貨門市、配送限制與付款備援必須另外核對。任何送單都可能建立真正的購買義務，不能把現貨商品測試當成無副作用的模擬。
