# 共用派單總管與單品／合單模式

## 實作範圍

本次只修改程式及離線驗證，沒有建立真實訂單。登入、人工驗證及既有付款備援保留；不繞過官方限購或排隊。

```text
FUNBOX／誠品的新鮮補貨訊號
  → 共用篩選（黑白名單、優先關鍵字）
  → 各帳號規則（購買帳本、剩餘額度、人工配送規則）
  → 每帳號獨立排序佇列
  → 單品一款一單／合單多款一單
  → 平台 API 執行器
  → 正式結果、逐款記帳、表格及 TXT
```

黑名單永遠優先，只排除購買，監控通知不受影響。FUNBOX 需命中白名單。誠品保留原有「黑名單以外皆可」／「只購買白名單」設定，不在升級時偷偷改變購買範圍。

優先關鍵字由左至右；同一優先組保留發現順序，其餘各帳號獨立隨機。同帳號一次只有一條改車／結帳線，各帳號可並行，但保留現有平台最多三線、全域最多四線限制。

## 帳本

| 平台／商品 | 採用規則 | 證據性質 |
| --- | --- | --- |
| 誠品 | 帳號曾購商品永久排除 | 使用者確認 |
| FUNBOX 隨機強化組 | 同帳號同款當日累計最多 3 件，可 2+1 | 使用者確認 |
| FUNBOX 一般款 | 同帳號同款當日最多 1 件 | 人工假設 |
| FUNBOX 重置 | 台灣午夜 00:00 換日期桶 | 使用者同意的假設，非已驗證官網規則 |

資料寫入 `state.json` 的 `commerce.autoPurchase.purchaseLedger`，按帳號身分而非僅 A／B 標籤計算。訂單以官方單號去重，午夜不刪除訂單或舊日誌。

送單前持久保存額度保留。結果不明的保留跨午夜／重啟仍生效；唯讀查單確認成立才轉正式帳本，或由使用者核對未成立後解除。取消訂單不自動返還額度：是否返還未確認。

舊資料缺日期／當日數量無法確認時保留保護，不推測免費額度。只涵蓋本機紀錄／已同步的訂單；其他裝置新買的 FUNBOX 訂單不會自動被此帳本得知，官方限購仍是最後裁決。

## 控制台

每帳號「帳密設定／設定」內可選：

- 單品：一款一單，維持原預設。
- 合單：多款一車，再送一張單；不是對同一車同時發出多個送單請求。

平台「合單上限與配送規則」可設定最多款數、集貨等待、加車期限、每單含運上限、允許缺款及禁止超商貨付的關鍵字。

初始合單參數：最多 5 款、集貨等待 500ms、加車期限 8 秒、含運上限 NT$1,500、允許缺款。這是新模式的安全預設，不是已測得的最佳搶購參數。原本帳號仍為單品，須自行選合單並儲存才使用。

加車期限是停止啟動下一款加車的期限；已發出請求仍須等待逾時／查車確認，整張訂單不保證 8 秒完成。誠品原有 30 秒交易窗口與有限送單重試保留。

## 合單執行

01 清車並核對 → 02 核對本帳號本批任務 → 03 依優先順序逐款加車 → 04 核對整車並封箱 → 05–10 結帳資料、紅利 0、配送付款及含運金額 → 11 有限送單 → 12 正式訂單核對 → 付款資料／保存／私人通知。

- 售罄／官方限購明確拒絕：允許缺款時排除該款，保留已加成功款；不允許缺款則不送。
- 加車逾時／5xx：先查整車，不直接重加；無法確認就停止本次建車，不宣告成功。
- 封箱期限：未開始的款列為未完成；不為湊滿購物車無限等待。
- 含運超額／金額不明／付款不提供：不送。誠品運費核對採保守費用，不猜免運資格。
- 官方明確忙碌拒單：沿用最多三次且受時間窗口限制的重試。
- 送單逾時／結果不明：保護整車，查單必須唯一匹配所有商品及數量；不重送、不清車、不拆單。
- 已成功：逐款記帳，不只把第一款標成已購。FUNBOX 隨機強化組若尚有日額度，仍須新鮮可購觀測及冷卻後才能建立補足任務。

既有單品路徑及付款備援保留。新合單不新增未驗證的誠品 LINE Pay API 契約；不可提供指定付款時會停止，不臆造付款資料。
