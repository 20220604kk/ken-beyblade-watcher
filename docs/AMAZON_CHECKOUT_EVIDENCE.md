# 日亞 02 快照與待核對恢復

## 使用方式

- 任務進入 02 時保存入口證據、收到結帳回應時保存回應；發生錯誤再保存失敗證據。一般缺貨輪詢不截圖。
- 控制台「永久訂單時間紀錄」內可點選 02 快照與「原因／HTTP」。快照和訂單紀錄一起保留，不受即時 LOG 清空影響。
- API 路徑使用當次實際收到的 HTML 離線渲染 PNG，不會為截圖重開官網或重送直購／送單。入口前一頁不代表結帳成功。
- 瀏覽器路徑保存實際頁面截圖。截圖失敗會明確顯示失敗，不拿說明圖冒充實際畫面。
- 舊紀錄若沒有保存回應，不能事後重建當時快照。

## 待核對不是自動重送

按「檢查」時，如果有待核對交易，先持久停止該任務，再進行唯讀核對；即使核對成功，也要重新勾選「啟動」才會再次購買。

- **尚未最終送單**：讀取官方購物車；確定空車後可解除交易鎖。如果仍有商品或無法確認空車，保留鎖並顯示後續處理方式，不自動清車。
- **已送出／結果不明**：只能先查官方訂單；不以空車推定失敗，不清除交易證據，不重送。
- **任務正在操作**：拒絕這次變更，不中斷正在進行的交易。

## 實作與保存

`amazon-jp-http.js` 接收回應 → `amazon-checkout-evidence.js` 非同步保存／離線渲染 → `amazon-order-history.js` 將證據附於訂單紀錄 → 控制台本機唯讀端點顯示。

儲存於 `data/records/amazon-product-orders/evidence/<record-id>/`，含 PNG、移除腳本與表單憑證的 HTML，以及 HTTP／去除查詢參數端點／錯誤原因 JSON。瀏覽器畫面仍可能包含可見收件資料，只保留本機，不能直接公開或上傳。`data/` 已排除於 Git。

快照不阻擋 API 結帳；同一訂單存檔序列化，避免背景快照與完成紀錄互相覆蓋。安全重載會等待背景快照保存完成。

## 驗證

以合成回應測試 404、非同步存檔、截圖失敗、三階段證據、單號保存、路徑限制與控制台呈現，並用隔離、無 Cookie、禁止外連的 Chrome 渲染器確認 PNG 可產出。這些測試不代表取得真實庫存或成立新訂單。
