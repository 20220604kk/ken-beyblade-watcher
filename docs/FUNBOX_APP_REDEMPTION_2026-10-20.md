# 方爸APP兌換：獨立特別任務

使用者於 2026-10-20 指定：沿用現有本地控制台與桌面小程序，不另開控制台；流程為可移除的獨立 JS 任務。預定時間採 **2026-10-21 10:00，Asia/Taipei**（原需求第 8 點的 10/20 與「明天」不一致，已於對話說明採 10/21）。

## 使用方式

1. 在原 FUNBOX 帳號表 **C 列，帳密設定旁按「特別」**。
2. 選擇黃蜂要塞、海怪扭擺或雄鹿戰角，填入各自序號；可新增、上移、下移、移除列。重複產品可以，重複序號不可以。
3. 按「儲存順序與序號」。序號以 AES-256-GCM 加密留在本機，不會回傳到頁面、紀錄或 Git。重新開啟時，空白序號欄可沿用已儲存序號。
4. 可先按「C 唯讀檢查」。過期登入應先用原 C 帳號登入工具處理，再啟用任務。
5. 按「啟用特別任務」並確認。C 立即改為紅框／紅字並由此任務專用；一般派單不再使用 C，A/B 的設定不變。預定時間到才開始加車。
   開始前 60 秒會預先核對 C 登入與門市；只有官方明確導向登入頁時，才沿用現有官方登入流程更新工作階段，不操作購物車。不繞過人工驗證。
6. 每列數量固定 1、各自一車一單。例：黃蜂序號甲 → 黃蜂序號乙 → 海怪序號丙，形成三張獨立訂單。
7. 依使用者最後修正，**只核對訂單總額 555 元，不限定單品價與運費如何拆分**；仍須指定序號已套用、單品 ×1、7-11 取貨付款、紅利 0。沒有付款備援，不改 ATM 或 LINE Pay。
8. 按「停用特別任務」停止後續派單；已送出的請求會等待結果及查單，不中斷後盲目再送。C 有未知交易時保留保護。全部完成後 C 仍維持專用，手動停用後才恢復一般派單。

目前預設僅在開始後 30 分鐘內開始新一筆，超過時段不補送。主流程同帳號完全依序，不同序號不合單、不平行加車。

## 檔案與可移除性

- 主流程：`src/optional-tasks/funbox-app-redemption.js`。
- 現有介面內的「特別」按鈕、填寫視窗與紅框：同目錄 `funbox-app-redemption-ui.js`。
- 正式程式只提供選配載入、HTTP 轉交、C 帳號保留及既有訂單的「特別任務」標籤；一般監控與結帳政策不套用兌換序號邏輯。
- 本機私有資料：`data/optional-tasks/funbox-app-redemption/`，包括 `.key`、`queue.enc.json`、`state.json`。不進 Git。
- 主帳本保留 `specialTask: true`、`taskKind: funbox_app_redemption`、逐步紀錄及正式單號。每個任務列有獨立 UUID，因此同產品的不同序號不會覆蓋訂單。
- 主狀態的 `externalAccountReservations.C` 是本機保留標記，避免任務檔意外被移走後 C 回到一般派單。它不提供跨機鎖。
- 安全停止後可按「移除此任務入口」。只寫入本機 `disabled.flag` 並隱藏入口，不刪單、不刪加密資料；下次啟動不載入此任務。重新安裝時移除該旗標再重啟。
- 也可在安全停止並確認無保留標記後，移走整個 `src/optional-tasks/` 中這兩個檔案並重啟；選配載入器不因檔案缺少而啟動失敗。不要刪除未決交易紀錄來解鎖。

## 查證到的官網協定

2026-10-20 的唯讀／經授權加車查證：

- 三個目標商品及使用者另列的龍神勇氣商品 JSON 當時都是 404；參考水藍龍神 JSON 可讀，標價 999999。
- 經使用者明確允許，在 C 空車暫加水藍龍神一件，讀取結帳頁與靜態程式後，只移除該測試品，重新確認空車。**沒有查詢或套用任何序號、沒有送出訂單。**
- 官網結帳前端來源：`https://cdn-general.cybassets.com/frontend/checkout/main.efb4f8e384292641cad5.js`。以下是該版本的實際網站請求，不是另外申請的官方商品 API。

| 步驟 | 網站請求及核對 |
| --- | --- |
| 查詢指定序號 | POST `/carts/<token>/coupons`，JSON `code`，與前端一致轉小寫；只接受回覆同一序號，明確 `err_msg` 則略過 |
| 套用序號 | POST `<cart>/apply_coupon`，`codes: [指定序號]`、`manually: true`、`apply_maximun_bonus: false`、`bonus_used: 0`、`cart_type: order` |
| 核對序號 | 重新讀官方結帳頁，必須只有同一張券，官方 `coupon_discount > 0`，紅利消耗與折抵均為 0；不限定折抵後單品價 |
| 配送付款 | 讀當車最新付款選項，使用 `seven_cod`；已核對的 C 門市資料可沿用，否則使用正常官方電子地圖回傳 |
| 金額與紅利 | 選店後再次設定紅利 0、重讀結帳頁，核對單品 ×1、含運及手續費總額 555；不限定單品／運費拆分，不把本地假金額當作官方折價證據 |
| 多購物車 | 只有出現官方選車頁時，使用唯一匹配指定規格的 `checkout_no_conflict` 表單／官方 React 資料；送單前再次核對完整單品車。不猜其他車、不合單 |
| 送單與查單 | 保存舊訂單基準、逐列送單意圖與預留額度後才送最終 POST；每列本次最多一次最終 POST，結果不明只做官方查單 |

本機研究資料留在忽略目錄，沒有將含會員資料的結帳頁或實際序號放入文件或 Git。

## 尚未完成實證的部分

使用者目前沒有可供查證的有效序號，三個目標商品也尚未開放，因此 **有效序號的伺服器回覆、實際折價及總額 555、特別商品真實 COD 成單尚未驗證**。

## 報錯、停用與復原

- 404／讀取暫時失敗：只重讀公開商品資料；正常重讀間隔至少 1 秒，不併發加車。429／503 至少冷卻 60 秒並遵守更長 Retry-After。
- 加車回應不明：只讀本車確認商品及數量；不重複加車。不能確認就保留 C 與現場。
- 序號套用回應不明：只重讀本車判定是否已套用，不直接重送套用請求。
- 官方明確序號不可用：核對只包含本任務商品後，只移除此一件，確認空車再進下一筆。
- 價格、商品、門市或紅利不符：不送單，保留現場。若確定沒有送單意圖，使用者可在任務視窗明確確認「移除本任務未送單商品」。
- 送單逾時、缺單號、非預期回覆：只查單，最多兩輪；依送單前基準比對唯一新單，再核對正式明細。仍不明就停止整個 C 序列，其他帳號保持原流程。
- 重啟遇到 `adding`／`coupon_applying`：轉購物車待核對。遇到送單意圖：轉未知訂單保護，不重送。可用「只查未決訂單」補查。
- 未知訂單不能用刪資料、清車或移除入口解除保護；需要官方訂單證據。
- 本機服務以 `127.0.0.1` 提供功能，變更請求需正確本機 Origin、Host 與本次服務隨機 CSRF token。
