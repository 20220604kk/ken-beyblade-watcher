**正常網頁與獨立 HTTP 下單皆已各成功一次比較實單。** 第四階段是最新結論：HTTP 已完成空車核對、報價、加車、結帳、JPY 送單及官方單號／詳細金額核對。它是網站內部協定，不是公開購買 API；尚未接入正式日亞任務。以下各階段的「未送單／純 API 未跑通」描述均是當時的歷史狀態。

本次未加車、未改數量、未進入結帳、未送單、未付款，未重播任何購買 POST。購物車頁確認本車為空、徽章為 0；「稍後購買」資料未操作。正式監控及帳號 A 自動任務未修改，也沒有重載服務。

1. **監控可以研究調整，但未直接換線。** 搜尋／品牌頁負責發現新 ASIN；已知 ASIN 的 AOD 報價可作為可購、自營賣家及價格的補充來源。必須看賣家，而非只看 Amazon 配送；並處理報價分頁、缺貨、限流、憑證與幣別。AOD 失效時仍保留既有商品頁路徑。是否更快、更穩還需要同條件多次驗證。
2. **自動下單可能減少頁面往返，但尚未證明。** 已知入口不等於完整契約；仍要驗證加車、結帳狀態、付款配送、最終送單與正式單號。商品頁沒有主按鈕並不一定是載入失敗，而有第三方報價也不代表符合我們自營原價條件。

### 本次確實找出的疏漏

即使配送免費，結帳預設 **TWD 換匯**仍出現 TWD 1.48 的額外費用，總額 TWD 63.52。送單前透過正常貨幣選項改成 **JPY ¥306**，再核對免運與不折點數，才提交。

因此送單護欄不能只有「Prime／免運」；仍須核對 **當次幣別、含運總額、附加費、點數、商品、數量、賣家與配送選項**。不能因會員身分推定所有商品、配送地區及配送方式都免運。

### 對兩項研究的直白結論

1. **監控值得增加已知 ASIN 的 AOD 報價直查，但尚不能直接把正式監控全換成裸 HTTP。** 它有機會減少重繪整個商品頁；新 ASIN 仍需搜尋／品牌來源發現。需要同條件重複比對價格、賣家、缺貨與限流，才知道是否真的更快、更穩。
2. **下單確實有內部 HTTP 入口，但純 API 加速未證明。** 這次成功的是正常瀏覽器操作及同步 Network 觀察，不是獨立 HTTP 適配器。需要補齊實際加車、結帳狀態及 session／CSRF 契約，才可比較 HTTP 與現行瀏覽器的速度。不能因觀察到最終 POST 就跳過官方核對或直接重播舊 body。

本次暫停日亞 A 自動任務以避免同時操作，完成後將原 ASIN、hybrid 模式、成功目標 1 次、運費上限 ¥500 與啟用設定恢復；沒有重設進度，沒有重載服務或修改其他平台。恢復後狀態仍保留「商品頁等待關鍵資料後仍未完整載入，將有限恢復」錯誤，故啟用設定恢復不等於原自動任務已成功完成一次掃描。這次一般商品成功不代表熱門陀螺壅塞時的成功率。

### 全 HTTP 成功的請求鏈

1. GET 官方購物車，核對真空車；不刪原有／稍後購買資料。
2. GET AOD，取得即時報價及 fresh CSRF／offer 契約。
3. POST 官方加車，一次、數量明確為 1；回覆確認購物車 1 件。
4. GET 官方 `/checkout/entry/cart`，沿用已儲存的付款與配送。
5. 根據官方提供的 JPY／MARKETPLACE 選項核對日圓 ¥306、運費 0，不折點數。
6. POST `/checkout/p/<flow>/spc/place-order`，一次；HTTP 302。
7. GET 官方完成頁，HTTP 200，確認訂單提交。
8. GET 官方訂單列表，從 **order-card 的正式識別資料**取得新單號。
9. GET `/your-orders/order-details`，核對該新單的商品與金額。

本次 API 路線的上述交易與查單使用獨立 Node HTTP client；沒有透過瀏覽器點擊加車／結帳／送單。另用瀏覽器閱讀同一張官方訂單，作為交叉核對及截图佐證。

### 初次走通時確實遇到的相容性問題

- **406：** 不完整的文件型 Accept 設定被拒絕；改成標準 `*/*` 後，原購物車路徑直接 HTTP 回覆 200。沒有 CAPTCHA，沒有繞過驗證或更换 IP。
- **數量空值：** AOD 的 hidden quantity 原本由官網 JavaScript 填寫。HTTP 路線須在 fresh 官方表單中明確送出使用者授權的 1 件。
- **405：** 幣別切換不是另一個已驗證的 POST API；網頁同時含有 TWD 與 JPY 報價，不能把隱藏的 JPY 報價誤當成已選日圓。正確方式是依官方選項把最終送單的 `currentCurrencyOption` 設為 MARKETPLACE，並核對對應 JPY 報價。
- **訂單列表解析：** 純 HTTP 的卡片在 link hydration 前已有官方 `data-csa-c-slot-id`。不得因找不到已渲染的詳情連結，就重送訂單；讀正式卡片 ID 後再查官方詳細頁。

研究程式位於 `scripts/amazon-http-checkout-comparison.mjs`，只限定此次商品／金額，不是正式自動下單模式。實單紀錄、計時及去識別化金額截圖保存在 Git 忽略的 `data/records/amazon-http-tests/`；源碼沒有實際既有單號、Cookies 或 CSRF 值。一次性登入資料讀取後已刪除。

本輪結束再次恢復日亞 A 原啟用設定與原商品、模式、目標、運費上限及價格容差，沒有重設進度或重載服務。已有 5 項離線安全回歸通過：不重送、缺基線不加車、未勾選偏好不帶入、拒絕跨網域表單、Cookie 網域／路徑隔離；它們不代表高流量下的成功率。
