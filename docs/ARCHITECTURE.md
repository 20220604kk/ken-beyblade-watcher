# 架構與執行邊界

## 組裝與狀態

`index.js` 讀取 `.env`、`config.json`，建立 StateStore、帳號資料庫、平台監控器、購買協調器、通知器與本機 HTTP 儀表。設定／狀態以本機檔案持久化；不是雲端多使用者服務。

主程式目前仍是大型組裝入口，`auto-purchase.js` 同時包含協調器與平台 adapter；不應把目錄分檔誤認為已完全解耦的插件架構。

## 監控與事件

`funbox.js` 合併官方商品來源，正規化商品身分與庫存；`shopping-sites.js` 依來源解析台灣購物網站、誠品搜尋／策展與商品狀態。日本來源由 `japan-auctions.js`、`amazon-jp-monitor.js` 處理。

StateStore 保存基線與已通知資料，避免同一觀測不斷重複通知。通知與購買分流，通知慢或限流不應被當成網站送單失敗。登入失效、來源不可讀與庫存為零是不同狀態。

文件以 FUNBOX、誠品、其他購物網站、日拍／日本商店、日亞五類區分，詳見 [平台監控邏輯](MONITORING.md)。這是功能分類，誠品仍由共用 `ShoppingSiteMonitor` 組裝，並非五個獨立服務。

## 派單與交易

1. `purchase-rules.js` 核對黑白名單、關鍵字、數量與配送規則。
2. `purchase-ledger.js` 按帳號身分追蹤已購及未確認額度，未知交易不在跨日或重啟時自動釋放。
3. `purchase-dispatcher.js` 排序帳號任務，選擇單品或合单批次。
4. `AutoPurchaseCoordinator` 控制帳號鎖、有限並行與工作生命週期。
5. 平台 adapter 清車並核對、逐款加車、核對紅利零／配送付款／總額，才允許送單。
6. 官方結果確認後逐款記帳、保存步驟及私人通知；逾時結果不明進入查單／人工核對保護。

同帳號同時間只允許一條改車流程。合單允許排除明確售罄款時，只排除該款；不因送單結果不明而拆單重送。

FUNBOX／誠品的付款方案、帳號限購政策、備援與未知結果處理，另外整理在 [自動下單功能](AUTO_PURCHASE.md)。監控 API 可讀、付款選項可見、正式訂單成立是三種不同證據，不互相替代。

## UI、通知與連接器

`dashboard.js` 提供本機路由及頁面，`dashboard-overview.js`、平台 `*-ui.js` 提供表格／狀態元件。瀏覽器取得本機狀態並呼叫操作 API。

`notifier.js` 路由 Discord／LINE 通知。Discord 公開情報與私人訂單目的地分開設定；私人目的地留空不能改以公開頻道代送。

`extensions/` 的蝦皮／愛電王連接器經配對向本機橋接器提交商品觀測。它们不是用來匯出 cookies 或繞過 CAPTCHA；人工驗證由使用者在官方頁面完成。

## 本機資料

`data/` 保存狀態、帳號加密檔、金鑰、瀏覽器 session 與來源快取；`records/`／`logs/` 保存訂單及日誌。這些目錄均不發佈。

本機帳號檔採 AES-256-GCM，金鑰也存於本機；取得整份資料目錄的人可能可解密。瀏覽器登入狀態亦視為秘密，不能因帳密檔加密就認定所有 runtime 資料都已加密。

## 已知限制

沒有完整雲端部署／多人權限隔離、沒有 exe、沒有保證平台 API 穩定的契約。LINE Pay 正式流程仍未完全串接。發佈版本移除實測與測試資料後，只保留語法檢查；正式交易驗收需另行受限授權，不應作為預設啟動操作。
