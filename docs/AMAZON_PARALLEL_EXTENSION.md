# 日亞 API＋插件雙路競速

## 這次做什麼

- 原 API 線照原本的帳號專用工作階段執行。
- 新插件使用普通 Chrome 的登入，建立不搶焦點的背景分頁，以真正的官網按鈕操作，不是假裝前端的第二條 API。
- 兩路獨立刷新，不等另一條網路回應。每條路同一補貨波最多取得一次送單授權，最多兩張訂單。
- 已確認成功時，取消另一條「尚未授權送單」的路；兩條都已授權則各自核對，可能成立兩張，由使用者取消重複單。
- 只將官網完成頁的正式訂單編號認定成功；purchaseId、進入結帳、點過按鈕都不算。

## 一次性安裝

1. Chrome → 擴充功能 → 管理擴充功能 → 開發人員模式 → 載入未封裝項目。
2. 選擇 `D:\codex\beyblade-watcher\extensions\amazon-race`。
3. 在這個 Chrome 個人資料登入正確 Amazon 帳號，開啟一張日亞商品頁。
4. 控制台「日亞自動下單」→「API＋插件雙路競速」→ 選 A／B／C → 產生配對碼。
5. 點插件，選相同任務、貼碼、讀取登入名稱，確認帳號與重複訂單風險，再按「連接背景執行」。

之後關掉插件的小視窗即可，主 Chrome 需保持執行。每個 Chrome 個人資料只連一組任務；要同時跑 ABC 前端，需三個分別安裝並配對的個人資料。沒有配對的任務仍只跑原 API，不冒充雙路已啟用。

插件不會讀取或搬運密碼、Cookie、信用卡資料，也不會自行登入或處理 CAPTCHA。顯示名稱只是防止誤切帳號的檢查，**不是唯一會員 ID**；首次任務與帳號的對應必須由本人確認。改語言不會被誤當換帳號。

## 三種類型的 LOG

01｜商品頁面｜發現直接購買

02｜安全結帳｜核對／送單

03｜取得訂單｜正式訂單編號／待核對

API、插件會標示來源。即時 LOG 與刷新次數只在記憶體中，清空不動訂單或送單授權。各路購買嘗試分別永久記錄，包含 route、raceId；不把另一路的失敗覆蓋成功。

## 保護規則

- 僅直接購買，不改用混合購物車送單。
- 同 ASIN、數量 1、自營／全新、JPY、原價限制、運費上限、不用點數、配送已確認，全部通過才授權。
- 最終授權先寫入本機狀態，再允許 POST／點擊；磁碟失敗不送單。
- 尚未執行最終送單的準備失敗可以重試：前兩次分別等待 2、5 秒，連續第 3 次失敗降速 30 秒，之後繼續監控重試，不永久停止。每次都取得新商品頁、新流程、新嘗試識別，不重用舊表單；**一次性限制針對最終送單，不是把未送單失敗也鎖死**。
- 插件同時把授權存到自己本機資料，再點一次。斷線或重啟只核對結果，不能重用授權。
- API 結果不明不會重送；另外獨立授權的插件路仍可完成同一波一次嘗試。
- 「立即購買」跳轉回應不明與「最後送出訂單」回應不明分開：前者可依 `direct_buy_now / buy_now / 同 ASIN / 數量 1` 的持久紀錄安全續跑，不查車、不清車；後者仍需查正式訂單。舊加車流程或證據不足不套用自動解除。
- 雙路模式不拿「新出現的同商品訂單」猜測為 API 的單，以免誤認插件的訂單。
- 配對存在或交易待核對時，停用待機自動清車；不在結帳中覆寫工作階段。登入／換商品／重設仍受交易鎖保護。
- 碰登入失效、驗證或錯誤則停止／冷卻該路。不保證不會被網站限流，不繞過驗證。
- 繼續有貨不會不斷開新一波；只有前波已結束、再次觀察缺貨後，才能開始下一補貨波。任務達成功次數仍會停止。

## 權限與背景運作

新插件獨立於愛電王／誠品插件，權限只涵蓋日亞、本機 3210、分頁／執行自己的 DOM 程式／儲存／排程。不要求 cookies、debugger 或所有網站權限。

配對碼只存雜湊，連線綁定插件來源與任務；不出現在網址／日誌／公開狀態。頁面 HTML 只暫時傳到本機核對，02 證據沿用本機去除腳本與敏感表單欄位後的離線快照，不上傳 GitHub。

最低 Chrome 120。採本機 WebSocket 與 20 秒應用層心跳維持背景工作，不依靠可能被節流的背景分頁定時器；但睡眠、Chrome 關閉、官網壅塞或實際網路耗時仍會影響速度，不保證固定 2 秒完成一輪。

## 驗證與限制

使用合成 ASIN／合成訂單編號，測試單路一次、雙路兩次、成功取消未送單路、兩路已送單、逾時／重啟、欄位不符、第三方賣家、點數、運費、假完成頁與配對來源限制。

另用獨立臨時 Chromium 個人資料載入實際 MV3 插件，將所有官網請求導到離線測試頁；不使用真實帳號、不建立真實訂單、不切換使用者工作視窗。這些測試不能代替正式 Chrome 安裝配對，也不能證明真實補貨時一定買得到。
