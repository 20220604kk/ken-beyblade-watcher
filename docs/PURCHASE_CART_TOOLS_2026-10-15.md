# FUNBOX／誠品：手動清車與帳號瀏覽器

## 已修改

- FUNBOX／誠品各自只有一個「一鍵全清」，清空該平台所有已設定帳號（含停用帳號）；移除單帳號清車按鈕。
- 帳號欄中的手機號碼是可點擊的連結，點擊即開啟該帳號瀏覽器；不增加每列按鈕，新增帳號也適用。
- 帳號表格改成百分比欄寬、窄視窗自動換行，不再強制 1200px／固定操作欄寬。
- 購買前不再讀取空車或刪除舊商品；誠品已預熱帳號直接核對派單、加車。冷帳號仍先驗證會員。
- 加車後仍核對全車品項與數量；有其他商品／多餘數量時停止，不會偷偷合買或清車。
- 自動心跳、每日保養改為登入檢查，不再自動清車。原有「手動保養」仍是明確要求清車的操作。
- 手動清車使用官方 API，刪除後重新核對空車。不送單、不付款。
- 全清會跳過下單中、帳號檢查中、等待核對未知訂單、人工視窗或帳號瀏覽器使用中的帳號，並列出各帳號結果；不會排到交易完成後才偷偷清車。
- 清車失敗會保留待確認狀態，重新成功清車後恢復；不立即開始新交易。
- 帳號瀏覽器載入該帳號既存 session，使用獨立可見 Chrome；不關閉背景購買工作器、不重新送帳密。
- 同帳號重複點擊只顯示原視窗。視窗開著時暫停該帳號派單，關閉後恢復；其他帳號照常。
- 瀏覽器內的手動帳號切換不會被盲目回寫到自動下單憑證。若官方 session 到期，仍需完成正常登入；此功能不是自動延長 token。

## 驗證

- 以隔離 API 測試覆蓋順暢、慢 10 秒、壅塞、加車逾時、全車污染、送單未知與有限重試。
- 新增帳號工具測試：單帳號鎖、忙碌／未知訂單拒絕清車、失敗解鎖、API 清車複查、同帳號瀏覽器重用與關閉回復派單。
- 新增控制台同源 POST 驗證，外部 Origin／缺少 Origin 禁止操作。
- 本次不建立真實測試訂單、不清除實際帳號購物車。
