# 10/21 特別任務失敗與修復

本次自動任務 **0／4 成單**；使用者另以手動完成四單。兩者必須分開記錄，不可將手動訂單補算成程式成功。舊批次已因售罄結束，修復部署不得重新啟用、重建序號或重送。

## 查核與原因

時間為台北 2026-10-21。09:59:05 預熱確認 C 登入有效；一般監控於 10:00:00 發現四款上架，10:00:01 已記錄四則上架通知。特別任務原排程為 10:00:05。

| 時間 | 實際紀錄 |
| --- | --- |
| 10:00:19、10:01:33 | 外層失敗，各安排 60 秒後重試；原碼未保存例外原因 |
| 10:02:41 | 第一次成功完成當輪會員頁 GET |
| 10:02:48、10:02:54 | 黃蜂兩筆第一次讀取商品成功，庫存已 0 |
| 10:03:01、10:03:22 | 雄鹿商品讀取成功，接著各約 15 秒後出現 `unexpected` |
| 10:03:56、10:05:10 | 再次外層失敗，各退避 60 秒 |
| 10:06:11 | 雄鹿兩筆讀取庫存 0，本批全部結束 |

四筆都沒有 `addAttempted` 或送單意圖；沒有進入套券及送單。當次唯讀核對 C 官方訂單沒有當日新單、購物車空車。原碼在每輪開頭強制讀會員頁，外層任何錯誤固定等 60 秒；商品後下一步為購物車 GET，截止 15 秒。雄鹿兩次錯誤依位置與耗時符合購物車逾時，但舊紀錄遺失原始分類，不能宣稱已取得其確切例外。

## 修復後契約

| 項目 | 行為 |
| --- | --- |
| 會員預熱 | 同一工作階段沿用；失敗在開賣前隔 2 秒重試，剩不到 14 秒不再插入新一輪會員讀取 |
| 任務主線 | 不再每輪先 GET `/account`；商品、購物車及送單前訂單列表各自核對所需資料 |
| 空車導向 | GET `/cart` 不自動跟隨導向。僅同一工作階段、同帳號且 120 秒內有登入證據時，接受官方 `/account/index` 空車導向；證據過期仍須讀頁確認，登入導向不接受快取證據 |
| 實站查證 | 修復時官方唯讀結果：會員頁 200、登入有效；`/cart` 回 302 至 `/account/index`，不須讀取其後整個會員頁。沒有 POST |
| 工作階段 | 預熱及重試沿用 API context；本機 session 檔變動即丟棄舊 context 與登入證據；關機釋放 context，每份回應即時釋放 |
| 普通錯誤 | 所有層級改為 1 秒、接續最多 2 秒退避；未上架固定 1 秒。新批次預設持續重試，不設 30 分鐘截止 |
| 慢請求 | GET 初始截止 5 秒；同端點連續逾時放寬為 8／11／12 秒，成功後重設。套券等指定短請求從 6 秒起、最多 12 秒。最終送單維持單次及原有截止，不套用讀取重試 |
| 真正限流 | HTTP 429／503 或明確 Retry-After 才進長冷卻，至少 60 秒且尊重較長伺服器要求；查單重試也不得覆蓋冷卻 |
| 已加車接續 | 優先讀原車，不用公開庫存 0 放棄已加車商品；加車結果不明先核對，不重複加入。只有連續三次確認空車後，才重查庫存並決定能否再加 |
| 優惠接續 | 原車已確認同券折抵及紅利 0，即跳過重查／重套；延遲重算先讀原車。官方已確認紅利 0 時省略重複歸零請求 |
| 不完整庫存 | `null`、缺欄位、空字串及非數字不當作 0，不因 `Number(null)` 誤判售罄 |
| 最終送單 | 單品 ×1、原券有效、紅利 0、7-11 取貨付款、含運總額恰好 555；持久保存意圖後只 POST 一次。未知只查單，不清車、不重送 |
| 診斷及介面 | HTTP 端點、狀態、耗時、截止、錯誤分類、下次重試時間；不保存請求內文、Cookie、序號或私人 token。開賣後顯示重試倒數，不再顯示等待 10 點 |

啟用及真實下單授權仍由既有本機 UI 控制。修復不代表自動替使用者建立新任務。其他帳號、一般監控及付款規則保持原設定。

## 驗證與接手

- 先跑 `npm ci`，再 `npm run handoff:phase1`，包含語法、完整離線回歸、隔離控制台、發佈掃描；收據只留本機，綁當下提交與來源。
- `test/funbox-app-redemption.test.js` 包含四張合成訂單、慢會員頁、購物車逾時、外層錯誤、工作階段更新、加車回應遺失、公開庫存歸零、優惠延遲、未知送單、限流及舊批次重啟。
- `test/funbox-app-redemption-ui.test.js` 以隔離瀏覽器驗證原控制台入口、序號回填、確認、秒數與重試診斷，所有 HTTP 使用合成回覆。
- 真正塞站期間的成功速度與正式 APP 券成單，本修復沒有重新實測；不得以合成四單聲稱實站已完成四單。
- 部署等交易及帳號操作空檔，核對原設定、序號密文與舊批次停用狀態；當次證據保存在本機 `artifacts/handoff/`。不把私人日誌、查核紀錄或真實序號提交 Git。
