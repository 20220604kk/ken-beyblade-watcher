# Ken 監控控制台

桌面雙擊 **Ken監控控制台** 即可。桌面是捷徑，排版修正版位於專案的 `artifacts/monitor-control-layoutfix/Ken監控控制台.exe`，使用 Windows 既有 .NET Framework 與 WebView2 Runtime，無須另外安裝 Electron；同資料夾的依賴檔案也須保留。

| 我要做什麼 | 按哪裡 | 結果 |
| --- | --- | --- |
| 開啟監控 | 第一顆顯示「啟動」時按下 | 啟動主服務及守護程式，各平台沿用原設定，不自動打開已停用的搶購 |
| 關閉整套 | 第一顆顯示「關閉」時按下 | 確認後停止，記住停止狀態；開機及每五分鐘復原排程不會擅自叫醒 |
| 重啟 | 重啟 | 確認後關閉再啟動，不清帳密、Cookie、購物車與訂單 |
| 看目前狀態 | 視窗上方／更新狀態 | 每四秒查本機控制台，區分在線、全部暫停、手動停止、未啟動及資料故障 |
| 開完整網頁 | 網頁 | 開啟原本的本機網頁 |
| 查啟動問題 | 系統日誌 | 打開 `logs/系統`，不自動上傳任何日誌 |

關閉控制視窗的 X **只關視窗，不關監控**。有交易、檢查、登入視窗或帳號操作時，控制工具會拒絕中斷，請等結束再試；不是額外提供一顆無條件殺掉送單的按鈕。

## 圓角與集合表新版

- 主控制列只有三顆：**啟動／關閉、重啟、網頁**。第一顆依實際服務狀態切換，不是只改文字。
- 新增多尺寸陀螺雷達圖示；桌面、工作列、視窗使用同一個圖示。卡片、按鈕與開關改為圓角。
- FUNBOX／誠品／日亞 ABC 直接嵌入原控制台的表格與操作，不建立第二套派單／付款流程。各平台可收合；設定及佇列／訂單步驟放在原表格下方的收合區。
- 底部「操作 LOG」與日亞即時 LOG 可收合。集合表不會因載入或刷新自行檢查帳號、清車或送單。
- WebView2 使用獨立的 `data/desktop-control-browser`，不是把零售網站帳號搬進小視窗；官方外連由使用者點擊後交給一般瀏覽器。
- 這次以背景編譯、自我檢查、隱藏的 Runtime 載入測試及隔離 Chrome 模擬介面測試驗證，沒有接管滑鼠、啟動可見測試視窗或更動監控設定。
- 更新採獨立目錄，不關閉正在使用的舊小視窗。使用者方便時關閉舊小視窗，再開桌面捷徑，即為新版；這不會停止背景監控。

## 開機／復原

- 勾選「允許開機啟動／異常復原」：Windows 登入時與既有每五分鐘工作可啟動服務。
- 取消勾選：不讓這兩個機制自動啟動，不影響正在執行的服務。
- **手動關閉優先**：即使仍有勾選，只要按過「關閉監控」，下次開機仍維持關閉。按「開啟監控」才解除。
- 守護程式有單一實例保護。控制工具也不允許同時進行兩個開關操作。
- 未實際重開 Windows 做測試；已直接執行同一個排程啟動入口，驗證停止狀態不會被解除。

## 圓角版現場問題的修正

- 原桌面網址使用 `/?desktop=orders`，但控制台只接受精確的 `/`，因此實際回傳 HTTP 404。改為共用 `OrdersView.DashboardUrl` 指向真正首頁；介面投影仍由嵌入腳本完成，不需要重載後端。
- 原表格測試用假路由將任何 `/` 路徑都回傳 HTML，掩蓋了網址錯誤。新版測試改經過真正的控制台 Router，明確確認舊網址 404、新網址 200。
- 表格只有 HTTP 成功且三個平台投影完成後才顯示；失敗時隱藏瀏覽器並顯示提示，15 秒後再試，避免露出 JSON／美化列印頁或不斷閃爍。
- 原固定高度裝不下文字與內距，改為依內容量測高度的配置；狀態說明與四張卡片的值不再以 Top／Bottom 固定高度互擠。
- 自繪卡片、開關清除完整底色，搭配雙緩衝及尺寸變動重繪，避免開關留下上一顆紅色按鈕的殘影。
- 背景證據包含 1000×760、1160×940、1400×1000 三種邏輯尺寸，100%／125%／150% 字型與尺寸縮放模擬，以及 LOG 開／關。這是本程式內的縮放模擬，不是更改使用者的 Windows 顯示設定。
- 隱藏 WebView2 檢查現在會實際 GET 控制台首頁並確認 HTTP 200 及三個平台節點；禁止任何非 GET 請求。舊版只驗證 Runtime 載入，不能證明頁面可用。

## 2026/10/17 強制重啟後

原 `data/state.json` 共 1,182,343 bytes 全為零值，已無法解析，不是帳密錯誤。經使用者同意：

1. 原損壞檔與修改前設定保存在 `data/recovery/2026-10-17T08-47-01-723Z-forced-reboot/`，沒有刪除。
2. 重建監控狀態，保留原監控設定、帳密、Cookie、獨立訂單檔及其他私人檔案。
3. FUNBOX／誠品全域及平台自動購買、日亞 A／B／C、暫停模式內的購買恢復設定全部關閉。
4. 控制視窗保留「歷史待核對」提醒。近期購買、限購、結果不明任務及監控基線不等於已恢復；必須另行核對，**不可因能開服務就打開搶購**。
5. 新狀態儲存增加落盤同步與每分鐘至多一次的前一份有效快照 `data/state.json.last-good`。故障時不默默回滾這份快照，以免回滾購買紀錄後重複下單。這不能保證硬體故障或斷電永不遺失資料。

`data/order-recovery-required.flag` 是復原提醒，不是已核對證明，也不是後端全域下單鎖；目前實際保護是已保存的各項購買開關全部停用。核對完成後才由使用者明確決定重新啟用。

## 維護

2026/10/17 後續決定：使用者不再要求找回故障前歷史，已移除上節的復原提醒旗標；不代表歷史已核對。日誌改採 [日誌保留規則](日誌保留規則.md)，不變更目前自動下單開關。

- 原本四個批次檔仍可使用，但 `04_強制停止監控.bat` 是舊的強制停止入口，沒有新控制視窗的操作中保護；日常請使用小工具。
- 建置新版：執行 `scripts/build-monitor-control.ps1 -OutputName monitor-control-rounded -UpdateDesktopIcon`。若該版小視窗正開著，改用新的 `monitor-control-短名稱` 輸出位置；不必停止監控主服務。SDK 固定版本來自 Microsoft 官方 NuGet，授權檔隨輸出保留。
- exe 只是控制器，**不是整套軟體的可攜版**；不要單獨搬到其他資料夾或刪除專案。
- GUI 不內嵌密碼、Webhook 或零售網站 Cookie，不會自動購物或切換帳號；原控制台的商品縮圖／官方外連仍可能使用其原有來源。
