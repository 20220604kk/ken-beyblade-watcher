# 日亞 A：今早失敗原因與 BX-11 實站驗證

日期：2026/10/18，Asia/Taipei。限定使用者指定的 B0C533Q31X（BX-11），停在正式送單之前。

## 今早 CX-20 的已確認證據

05:01–05:06 的獨立購買紀錄共 18 筆：17 筆在商品頁沒有可用直購按鈕，1 筆於 05:06 送出直購請求後收到 HTTP 404，未取得正式結帳回應、未進行最終送單。

- 失敗檔案：`data/records/amazon-product-orders/1792271182441-aabdc877-bd07-43a6-8c9a-e63fc1d6b9f3.json`。
- 實際失敗端點：`POST /gp/product/handle-buy-box/ref=dp_start-bbf_1_glance`。
- 官方錯誤回應為「找不到頁面」。不能據此宣稱 CX-20 已售罄或不補貨。
- 舊版本先讀 AOD 報價，再讀商品頁；兩者並非同一個可操作買框。有報價不代表當下有立即購買按鈕。17 筆不能都算成可成交機會，也不能證明都沒庫存。
- 沒按鈕的失敗還被加上約 15 秒退避，實際相鄰嘗試約 18 秒。這會放大報價／買框不一致的影響。

## 實站找到並修正的程式問題

1. 忽略送出按鈕的 `formaction`，誤用外層表單的舊 action。BX-11 官方按鈕明確指定 `/checkout/entry/buynow`；已改為遵循按鈕的 action／method／encoding，拒絕跨站及未知編碼，不硬猜備援端點。
2. 只收集表單內的子節點，未遵循 HTML 的 form owner；會夾入指定給其他表單的 CSRF 欄位。現在依真正的表單歸屬收集欄位，也包含在表單外但明確歸屬本表單的控制項。
3. Tango 結帳頁不提供商品 ASIN 超連結，而是在該筆商品的 `#col-item-block-description > span.aok-hidden` 中顯示。現在精確讀取該筆商品內的官方識別，不由品名或目標 ASIN 猜填。
4. 結帳階段的 404 不再標成商品頁不存在。已出直購 POST 而未完成核對，仍保留待核對；不解除不明交易鎖、不盲目重送。

只有 A 的 API fast lane 改為直接讀商品頁。一般 JPY 報價不再讀 AOD；若商品頁顯示外幣且無可信 JPY，才讀 AOD 並要求完全相同的 fresh offer，不能自行換算或套用另一賣家。
