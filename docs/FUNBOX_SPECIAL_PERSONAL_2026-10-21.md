# FUNBOX 個人特別任務管理

依 10/21 使用者要求，僅保留本機個人使用：刪除對外 AI 移植文件，兩個分享 ZIP、分享資料夾及匯出工具移至 Windows 資源回收筒。原監控、任務 JS、私人序號、訂單與診斷紀錄保留；不提供分享／匯出入口。

## 介面與操作

1. FUNBOX 自動下單工具列（新增帳號、補貨前檢查、一鍵全清旁）保留唯一「特別」按鈕；移除 C 帳號列中的舊入口。
2. 無現行特別任務時，先選擇已設定且已啟用的 A～N 帳號，再按「指定」。此動作只保留該帳號供本次任務使用，不會啟用下單；其他帳號不變。
3. 同一原控制台彈窗填寫產品、序號及排序。按鈕單排、不換行，每個最多兩字：新增、儲存、檢查、啟用、查單、結束、關閉。狹窄視窗可橫向捲動；需要處理原車時另顯示同排「清車」。
4. 已指定帳號顯示紅框、紅字及特別任務狀態；序號設定可編輯，啟用仍須原有真實訂單確認。執行中不能修改內容。
5. 「結束」停止派單並等待當前請求完成。無未決交易／未確認購物車後，取消尚未派送項目、保留紀錄及序號、撤除帳號保留、移除紅框與標示，恢復原先一般任務資格，不強制開啟原本關閉的帳號。
6. `unknown`、`cart_review` 等未決狀態不能強行釋放；介面顯示原因，繼續透過查單／明確的本車清理核對。
7. 結束後再指定帳號會建立新批次，舊狀態與原序號密文歸入本機 `data/optional-tasks/funbox-app-redemption/history/`；不復用舊序號、不修改既有訂單，也不補算手動訂單為自動成功。

## 接線與驗證

- `accountSlot` 持久保存；舊資料沒有此欄時沿用 C。互斥鎖、身分、門市、訂單紀錄及登入檔均使用所選帳號；A 使用正式歷史檔 `funbox-session.json`，其他帳號使用 `funbox-account-<slot>-session.json`。
- 一般派單與帳號工具依任意 slot 的持久保留標記排除，模組缺失也保留保護。結束寫檔後若程序中斷，重啟可完成移除該任務的殘留保留標記。
- HTTP 新增同源 CSRF 保護的 POST `assign {accountSlot}`、`finish {}`。舊的停用路由保留相容；不在新介面提供移除整個外掛入口。
- 回歸驗證：`test/funbox-app-redemption.test.js`、`test/funbox-app-redemption-ui.test.js`；使用假帳號與合成訂單，包含多帳號歸屬、結束恢復、未知不釋放、單排短按鈕及工具列入口。完整驗收使用 `npm run handoff:phase1`。
