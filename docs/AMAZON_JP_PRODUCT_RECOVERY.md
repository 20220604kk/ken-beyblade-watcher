# 日亞單品：讀頁恢復與送單核對

> 更新：正式單品任務預設改用 [API 主線](AMAZON_JP_API_WORKFLOW.md)。下列讀 DOM／點擊規則只適用保留的明確 `checkoutTransport: "browser"` 路線，API 失敗不自動轉前端重送。

## 適用範圍

日亞 A／B／C 商品頁任務。仍使用各帳號的持久瀏覽器結帳，不改成未經驗證的購買 API。保留「補貨訊號」及使用者已選用的「訊號＋五秒輪詢」模式。

## 正常流程

1. 接到符合條件的同 ASIN 訊號，或輪詢到可購報價。
2. 等商品名稱、價格、賣家與可操作購買按鈕就緒。條件等待最多 2 秒，並非每次固定等 2 秒；單次 DOM 讀取另有 3 秒上限。
3. 核對官方原價、自營賣家、目標商品與限購狀態，優先立即購買；加車路徑仍做購物車隔離核對。
4. 同一帳號一次只有一個檢查／交易。結帳期間的新訊號不刷新該頁，不產生重疊送單。
5. 以可操作性檢查點擊，等待頁面／階段變化；不使用 JavaScript 強制點擊。
6. 最終送單前再次核對：官方結帳網址、目標 ASIN／型號、只有 1 件商品、自營賣家、配送資料、已知運費及含運總額。
7. 每帳號預設運費上限 **¥500**，可在控制台調整。未知運費不視為免運；含運總額扣除運費不能超過官方原價容許範圍。
8. 單次送出後，需完成頁證據及正式訂單編號才記成功。結果不明改為待核對，停止自動刷新／重送；先由使用者確認官方訂單。

## 異常處理

| 情況 | 處理 |
| --- | --- |
| 明確缺貨 | 正常待命，不洗失敗通知 |
| 慢載入／空白 | 先短等；連續失敗按 2／5／15／30／60 秒退避；第二次失敗起只重開商品頁一次，保留帳號工作階段 |
| 商品頁不存在 | 等待 5 分鐘再檢查 |
| HTTP 429／503 | 至少退避 60 秒，遵守更長的 Retry-After；新訊號不能繞過期限 |
| 登入失效／人工驗證 | 暫停該帳號，等待使用者處理；不繞過驗證 |
| 結帳商品、數量、賣家、配送或金額未知／不符 | 不送單，記錄錯誤；不自行放寬條件 |
| 送單後逾時／沒有正式單號 | 待核對，不重送、不返回購物車重新購買 |

## 診斷與驗證界線

步驟記錄保留 HTTP 狀態、頁面標題摘要、正文長度、是否有名稱／價格／按鈕、等待結果及耗時；不記錄 Cookie、整段正文或請求頭。

回歸測試使用模擬頁面與封鎖外網的臨時瀏覽器，涵蓋延遲載入、不可見按鈕、空白、缺貨、驗證、金額解析、運費上限、訊號互斥及不明送單。這不等於目前 Amazon 真實結帳頁所有版型已驗證，也不保證補貨成功率。正式購買測試需另行明確授權。
