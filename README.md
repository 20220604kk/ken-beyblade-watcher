# Ken Beyblade Watcher

戰鬥陀螺商品監控與本機管理儀表。整合 FUNBOX、誠品線上及其他購物來源，提供新品／補貨通知、多帳號任務派送、單品／合單購買流程與訂單紀錄。

這是精簡的程式發佈版本，不是作者的個人監控環境備份。儲存庫目前維持私人，尚未選定開源授權；原始碼可見不等於已授權自由散布或商用。專案與各購物平台沒有官方合作關係。

## 主要功能

| 功能 | 內容 |
| --- | --- |
| 監控 | FUNBOX 多來源商品資訊、誠品搜尋／策展／商品狀態，以及其他已支援的購物與日本商品來源 |
| 通知 | Discord 公開商品情報與私人訂單通知分流；另保留 LINE Messaging 通知整合 |
| 派單 | 黑名單排除 → 白名單資格 → 心願關鍵字優先 → 帳號購買額度與配送規則 → 獨立帳號佇列 |
| 購買 | FUNBOX／誠品的單品一單、合單多款一車；同帳號序列化，不同帳號有限並行 |
| 結帳保護 | 清車核對、強制紅利歸零、配送與付款核對、含運金額上限、有限重試與結果不明保護 |
| 訂單管理 | 表格式結果、逐步耗時、TXT 匯出、官方訂單狀態查詢與本機購買帳本 |
| 商品資料 | 售價基準、BX／UX／CX／配件／聯名／對戰盤分類與名單操作；可選用自行設定的 Google 試算表 |
| 瀏覽器連接器 | 蝦皮與愛電王 Chrome 擴充功能，將商品觀測傳回配對的本機儀表 |

監控可使用 API、HTML 解析或瀏覽器，取決於各來源。FUNBOX／誠品的主要購買執行器使用官方網站端點；登入、人工驗證、首次門市設定或特殊付款仍可能需要官方網頁。不是所有平台都支援自動購買，也不是全程完全不需瀏覽器。

## 平台監控邏輯

| 類別 | 讀取方式 | 判斷與用途 |
| --- | --- | --- |
| FUNBOX | 分類、集合頁、搜尋 JSON API；必要時補讀商品規格 | 合併商品身分與庫存，辨識新品、恢復可購與庫存變動；合格商品交給派單總管 |
| 誠品線上 | Holmes 搜尋 API、策展來源、商品 `purchase_status` API | 搜尋找新品，策展補足探索，可購狀態核對候選；現行主入口採 API-only，不以瀏覽器輪詢代替失效 API |
| 其他購物網站 | 依網站使用 JSON API、HTML／商品頁解析 | 分專區保存基線，追蹤新品、規格與補貨；例如 momo、森森、童無忌及 MM 小舖，是否啟用由設定決定 |
| 日拍／日本商店 | 網頁解析；部分來源先 HTTP、失敗後瀏覽器；愛電王可用 Chrome 橋接 | 篩選 BEYBLADE X、新品與恢復販售；跨來源同款通知去重。「日拍」是介面分類，不代表自動競標 |
| 日亞 | TAKARA TOMY 定價表、Amazon 搜尋／品牌頁與商品頁 | 建立 ASIN 名單、輪替核對官方賣家與價格；通知新品可購或官方原價恢復販售，不把第三方溢價當原價補貨 |

各來源有自己的排程、快取與失敗處理。監控看到「可購」只是候選訊號，不代表庫存已保留或訂單成立。詳細來源、頻率與去重規則見 [平台監控說明](docs/MONITORING.md)。

## 自動下單功能：FUNBOX／誠品

這一層與監控分開：先依黑白名單與優先級篩選，再核對各帳號限購、配送與登入狀態，建立帳號佇列。每帳號可選單品一單或多款合單；同帳號不並發改車／送同一張單，不同帳號有限並行。

| 平台 | 主要下單路徑 | 付款與關鍵保護 |
| --- | --- | --- |
| FUNBOX | 登入 session → API 清車與加車 → 讀取結帳契約／選項 → 送單 → 官方訂單明細核對 | ATM／7-11 取貨付款；條件允許時有宅配 LINE Pay 備援。強制紅利 0、即時規格／數量上限、含運金額核對 |
| 誠品 | 本帳號 API session → API 清車與加車 → 結帳資料／報價核對 → checkout → 查單／ATM 資訊 | 宅配 ATM／具有效門市資料的 7-11 取貨付款；缺超商資料可檢查共用宅配 ATM 備援。LINE Pay 正式憑證串接尚未完成 |

成功、失敗與結果不明分開處理；送單逾時不直接重送。詳細流程、派單規則、補救與支援邊界見 [自動下單說明](docs/AUTO_PURCHASE.md)。

```text

                          └─ 派單總管 → 帳號佇列 → 購物車／結帳
                                                   → 查單／帳本／步驟紀錄
本機 HTTP 儀表 ← 狀態、設定、訂單與操作 API
```

## 安裝與啟動

主要使用環境為 Windows，需 Node.js 20.18.1 以上與 npm。未提供 exe；其他作業系統可自行以 Node 啟動，但 Windows 啟停腳本不適用。

1. 取得本儲存庫並進入專案目錄。
2. 雙擊 `install.bat`，安裝套件及 Playwright Chromium。
3. 安裝器在檔案不存在時，複製 `.env.example` → `.env`、`config.example.json` → `config.json`；不覆蓋既有設定。
4. 執行 `01_啟動監控.bat`，開啟 <http://127.0.0.1:3210/>。
5. 先設定來源、通知、帳號、收件資料與黑白名單，再自行啟用需要的監控／購買功能。

命令列方式：完成設定與依賴安裝後執行 `npm start`。程式依賴本機 `config.json`，不能只下載 `src/`。

範例預設關閉各監控與自動購買；帳號、收件人、門市、結帳範本及通知憑證均不隨專案附送。空白商品白名單不應直接開啟購買。宅配 ATM 亦需要本帳號有效登入及收件資料。

| Windows 入口 | 動作 |
| --- | --- |
| `01_啟動監控.bat` | 手動啟動服務 |
| `02_重啟監控.bat` | 重啟本專案服務；執行前應避開送單中的帳號 |
| `03_開啟監控網頁.bat` | 只開控制台，不代表啟動或停止服務 |
| `04_強制停止監控.bat` | 停止服務並保留停用標記 |

關閉網頁不會停止背景監控。自動復原排程不由下載專案自動安裝，須另外執行並理解 `scripts/install-monitor-health-task.ps1`。

## 購買邏輯與限制

- 黑名單優先；預設採白名單模式，命中白名單後再判定優先級及帳號資格。
- 合單是「逐款加入同一車，核對後送一張單」，不是對同一車並發多次結帳。
- 加車結果不明先查車；送單結果不明先查單並保護帳號，不盲目重送或清車。
- 成功必須有官方訂單證據；HTTP 200、本機測試通過或拿到付款選項不等於購買成立。
- 平台限購規則與重置時間可能改變。本機帳本只涵蓋已記錄／同步的訂單，官網仍是最終裁決；不應用多帳號繞過平台限制。
- ATM／超商取貨付款是否可用，由官方即時選項、商品配送限制及本帳號範本共同決定。登入／人工驗證／排隊失效時不繞過網站保護。
- 誠品 LINE Pay 備援仍缺正式環境的一次性付款憑證串接與實單驗收，不宣稱已完整支援。LINE Messaging 通知與 LINE Pay 是不同功能。
- 網站端點與回應結構可能變更；不保證下次補貨成功率、速度或訂單張數。請遵守網站條款、限購與流量限制。

## 發佈版本範圍

已移除測試套件、歷史補貨重播、實測報告／截圖、演練腳本與模擬商店內容；不把測試商品、固定個人試算表或作者電腦路徑當成使用者預設。

FB／Google 表單能力已退役，不隨此版本提供；`facebook-retired.js` 及停用的沙盒相容邊界僅用來拒絕舊入口。少量共用函式保留相容性，不代表功能仍啟用。

`npm run check` 與 `npm run check:edion` 提供語法檢查，不連線下單。這份精簡版本不附本機開發環境的完整回歸測試，語法通過不是端對端購買驗證。
